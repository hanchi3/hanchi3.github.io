web-gee-1 中框架实现的功能

  1. 路由映射
    框架通过 Engine 结构体持有一个路由映射表 router，该映射表将 HTTP 请求方法（如 GET 或 POST）和 URL 路径（如 /hello）映射到一个处理该请求的 处理函数（HandlerFunc）。用户通过框架提供的 GET 和 POST 方法可以将特定路径的请求与处理函数绑定。

  2. 请求路由
    框架使用 ServeHTTP 方法来实现路由功能，它会检查路由映射表，并根据请求的路径和方法来调用相应的处理函数。如果找不到匹配的路由，就返回 404 错误。

  3. 简化的 Web 服务器启动
    Run 方法提供了一个简单的接口来启动 HTTP 服务器。它将请求交给 ServeHTTP 方法处理，从而实现路由和请求的分发。用户只需要调用 Run 方法并指定监听的地址，框架就会启动 HTTP 服务器并处理请求。

  4. 中间件的实现基础
    尽管框架本身没有显式实现中间件的功能，但 HandlerFunc 的设计为用户扩展中间件提供了基础。用户可以通过 HandlerFunc 类型将多个处理函数链式组合，进而实现类似中间件的功能（例如请求的预处理、响应的修改等）。

使用框架后启动Web服务 main.go

gee.go

当用户调用 (*Engine).GET() 方法时，会将路由和处理方法注册到映射表 router 中。
(*Engine).Run()方法，是 ListenAndServe 的包装。

Engine实现的 ServeHTTP 方法的作用就是，解析请求的路径，查找路由映射表，如果查到，就执行注册的处理方法。如果查不到，就返回 404 NOT FOUND 。
