介绍日志的核心功能

在许多Go语言项目中，一个好的日志记录器一般期望能够提供下面这些功能：

  • 能够将事件记录到文件中，而不仅仅是应用程序控制台。
  • 日志切割：能够根据文件大小、时间或间隔等来切割日志文件。
  • 支持不同的日志级别。例如INFO，DEBUG，ERROR等。
  • 集成到 Gin 框架中，自动记录请求的日志。
  • 自定义日志输出格式，能够打印基本信息，如调用文件/函数名和行号，日志时间等。

go 标准日志库 log

Go语言提供的默认日志包是https://golang.org/pkg/log/。

自定义 Logger 实例（log.New）

log标准库中还提供了一个创建新logger对象的构造函数–New，支持我们创建自己的logger示例。
使用 log.New 可以创建多个独立的日志实例，每个实例都可以有不同的配置。可以为每个实例设置不同的输出目标、前缀、日志标志等，完全根据需要定制。不会影响全局日志配置。

Uber-go 第三方日志库 Zap

为什么选择Uber-go zap

  • 它同时提供了结构化日志记录和printf风格的日志记录
  • 它非常的快

Zap提供了两种类型的日志记录器—Sugared Logger和Logger。

在性能很好但不是很关键的上下文中，使用SugaredLogger。它比其他结构化日志记录包快4-10倍，并且支持结构化和printf风格的日志记录。

在每一微秒和每一次内存分配都很重要的上下文中，使用Logger。它甚至比SugaredLogger更快，内存分配次数也更少，但它只支持强类型的结构化日志记录。

配置Zap Logger

getLogWriter 使用 lumberjack.Logger 实现日志文件的切割和管理，配置了日志文件的大小、备份数量和最大保存时间。确保日志文件不会无限制增长，并能定期滚动和清理。

getEncoder 函数创建并返回一个 JSON 编码器，配置了日志的输出格式。该编码器决定了日志记录时如何组织时间、级别、持续时间和调用者信息等。
zapcore.NewJSONEncoder(encoderConfig) 使用上面配置好的 encoderConfig 返回一个 JSON 编码器，该编码器将会把日志记录转换成结构化的 JSON 格式。

Init 函数用于初始化日志记录器。这段代码完成了 Zap 日志系统的初始化工作，并配置了全局日志记录器。

GinLogger 中间件

  • 记录每个请求的日志
  • 性能监控
  • 日志结构化

GinLogger 中间件用于记录 Gin 框架的 HTTP 请求日志。它会记录每个请求的路径、请求方法、状态码、请求 IP、用户代理、请求耗时等信息。
返回 gin.HandlerFunc 类型的函数，是 Gin 中间件的类型，签名是 func(*gin.Context)，表示处理 HTTP 请求的函数。GinLogger 中间件会被注入到 Gin 的路由中，拦截并处理每个 HTTP 请求。
c.Next() 会让 Gin 继续处理请求，执行下一个中间件或请求处理器。在调用 c.Next() 后，Gin 会继续处理后续的逻辑。阻塞当前中间件的执行，直到后续的处理完成，因此 cost 的计算要等所有中间件和请求处理完成后才会执行。

GinRecovery 中间件

  • defer + recover 机制在发生 panic 时能够捕获错误
  • 检查 panic 错误是否为“连接断开”错误
  • 如果是，记录日志（lg.Error），传递给 Gin 框架的错误处理系统 c.Error(err)，c.Abort()，return
  • 非网络的 panic 错误，根据 stack 参数的值，记录堆栈信息（debug.Stack()）/错误和请求信息，并没有阻止程序继续运行
  • c.AbortWithStatus(http.StatusInternalServerError) 中止请求的进一步处理，并返回 500 Internal Server Error 响应，让客户端知道发生了服务器端错误，但服务器不会崩溃或退出

defer + recover 机制:
defer：这表示在 GinRecovery 函数中任何地方发生 panic 时，都会执行 defer 语句内的代码，确保程序能够恢复（recover()）并记录错误。
recover()：是 Go 的内建函数，用于捕获和处理运行时的 panic，它会恢复正常的程序流程。若没有发生 panic，recover() 返回 nil。

GinRecovery 函数，返回一个 gin.HandlerFunc 类型的函数。stack 参数：如果设置为 true，表示在发生 panic 时记录堆栈信息；否则，只记录错误信息。

注册logger中间件

在 main.go 中，初始化日志记录器（logger）。它调用 logger.Init 函数，传入日志配置和运行模式，初始化 zap.Logger 实例 lg，它是全局的日志记录器。

在 routers.go 中，将自定义的日志中间件 logger.GinLogger() 和错误恢复中间件 logger.GinRecovery(true) 绑定到 Gin 的路由（r）上。都使用了实例 lg，lg.Info 用于记录请求的详细信息，lg.Error 来记录错误的详细信息。

使用Lumberjack进行日志切割归档

在 getLogWriter 中使用了 lumberjack.Logger 实现日志文件的切割和管理。Zap本身不支持切割归档日志文件,但我们可以使用第三方库Lumberjack来实现。
