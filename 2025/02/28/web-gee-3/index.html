web-gee-3🚀 前缀树实现动态路由 Router

Created2025-02-28|Updated2025-02-28|轮子
|Word Count:1.9k|Reading Time:7mins|Post Views:

web-gee-3 中框架实现的功能

  1. 前缀树的使用：节点结构（node），插入操作（insert），查找操作（search）。

  2. 路由注册和匹配：

  • router：
    r.roots表： [HTTP 方法GET、POST] : *node 根节点。
    r.handlers表： [method + “-“ + pattern] : 处理函数（HandlerFunc）。
  • 路由注册（addRoute）：
    将路由模式插入到对应 HTTP 方法的根节点r.roots中；将路由模式和处理函数（HandlerFunc）注册到 r.handlers 中。
  • 路由匹配（getRoute）：
    根据请求的路径和方法查找匹配的路由。若匹配成功，则提取路径中的参数并存储在 Params 中。
  1. 请求处理 和 上下文管理
    handle函数调用getRoute，根据请求的路径和方法找到匹配的路由，提取路径参数到Context的字段后，调用对应的处理函数（HandlerFunc）。

Gin 框架中的动态路由

  • 在 Gin 框架中，动态路由可以使得同一个路由可以处理不同的请求路径，基于路径中的参数来执行不同的逻辑。
  • 原理概述：
    Gin 框架通过一个强大的路由匹配器来实现动态路由。这个路由匹配器基于 前缀树（Trie 树）或类似的结构来将请求路径与路由规则匹配。
  • 模式1: 占位符（参数匹配），用 : 符号来定义动态路由的参数。
    例如 /p/:lang/doc，可以匹配 /p/c/doc 和 /p/go/doc。
  • 模式2: 通配符，使用 * 可以匹配路径中的多个部分。例如，GET /files/images/pic.jpg，filepath 会被设置为 images/pic.jpg。
    例如 /static/*filepath，可以匹配/static/fav.ico，也可以匹配/static/js/jQuery.js，这种模式常用于静态服务器，能够递归地匹配子路径。
    本文要实现的动态路由也是要具备以上两个功能。

前缀树

为什么用前缀树

HTTP请求的路径恰好是由/分隔的多段构成的，因此，每一段可以作为前缀树的一个节点。我们通过树结构查询，如果中间某一层的节点都不满足条件，那么就说明没有匹配到的路由，查询结束。

前缀树的插入 – 路由注册

插入：开发服务时，注册路由规则，映射handler方法。在router的addRoute方法里被调用。
将一个路由规则（pattern）插入到 Trie 树中。递归查找每一层的节点，如果某个部分不存在，就会创建新的节点。
重点：在叶节点中才有 pattern 字段

前缀树的查找 – 路由匹配

匹配：访问时，匹配路由规则，查找到对应的handler。在router的getRoute方法里被调用。
递归查询每一层的节点，由于叶子结点中才有 pattern 字段，使用n.pattern == “”来判断路由规则是否匹配成功。
退出规则是，匹配到了*，匹配失败，或者匹配到了第len(parts)层节点。

将前缀树应用到路由 router.go

路由表的设计（已经不是map了）

addRoute

由 addRoute 可看出路由关系的设计。

  • roots:key 是 HTTP 方法（method），比如 GET、POST
    value 是一个 *node 类型的指针，表示该方法下的路由树的根节点。

  • handlers:key 是一个由 method 和 pattern 拼接而成的字符串，比如 “GET-/p/:lang”
    value 是一个 HandlerFunc，即实际的处理请求的函数。

  • 相同的 路由模式（如 GET-/p/:lang），对应的树节点 和 处理函数 是一一对应的。

getRoute

跟据 HTTP 请求的 method 和 path 查找对应的路由节点，并提取出路径中的参数（如 :lang、*filepath）等信息。
params 用于存储从 URL 路径中提取的动态参数（如 :id、:post_id）和它们对应的值。params["id"]="123"

handle 核心部分

handle 中比较重要的一点是，在调用匹配到的handler前，将解析出来的路由参数赋值给了c.Params。这样就能够在handler中，通过Context对象访问到具体的值了。
函数 handle 是 Gin 框架路由处理的核心之一，它负责接收和处理 HTTP 请求，匹配相应的路由，并执行相应的处理函数。它的主要作用是根据请求的 Method 和 Path 找到对应的路由节点，然后执行与该路由匹配的处理函数。

Context 的变化 context.go

在 HandlerFunc 中，希望能够访问到解析的参数，因此，需要对 Context 对象增加一个属性和方法，来提供对路由参数的访问。我们将解析后的参数存储到Params中，通过c.Param(“lang”)的方式获取到对应的值。
