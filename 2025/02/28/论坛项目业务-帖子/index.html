建立数据模型

  • models/post.go：
    Post -（VO），是一个表示业务实体（例如，数据库中的帖子）的对象。包含了帖子相关的基本属性，它主要用于表示帖子本身的核心业务值。与帖子的数据库表结构完全一致。
  • 解析字段标签：
  • json:"<json_key>"：
    json 标签指定字段在 JSON 编码/解码 时的行为，其中 <json_key> 是希望在 JSON 数据中使用的字段名。"-" 表示忽略该字段，即当你将结构体编码为 JSON 时，这个字段不会出现在结果中。同样，解码时也会忽略传入 JSON 中的该字段。
  • db:"update_time"：
    db 标签指定字段在数据库操作中使用的列名。这个标签通常用于与数据库进行交互时，帮助将结构体字段与数据库列映射起来。

ApiPostDetail -（VO），是用来表示单个帖子的详细信息的，将帖子的基本信息（来自 Post 结构体）和附加信息（如社区信息、作者名称、投票数等）组合在一起，供 API 响应使用。

*Post 和 *CommunityDetailRes 被匿名嵌套，这意味着：
ApiPostDetail 自动拥有 Post 和 CommunityDetailRes 的所有字段和方法。可以直接访问 Post 和 CommunityDetailRes 的字段 (方法提升)，类似 OOP 继承。

  • models/params.go
    ParamPostList，专门存储 query 参数的结构体。

form 标签用于在处理 HTTP 请求时，尤其是从表单数据中获取字段时指定表单字段的名称，表示从 HTTP 请求的 form data 中读取相应字段的数据。

  1. 执行事务

在 CreatePost 函数中，pipeline 用于 批量执行多个 Redis 命令，提高性能。它的原理是 减少网络通信次数，一次性把多个命令发送到 Redis 执行，而不是一条一条地发送。

这里使用了 TxPipeline()，它表示 一个**带事务（Transaction）**的 Pipeline，保证 所有命令要么全部成功执行，要么全部失败。client.TxPipeline() 返回一个 Pipeline 对象，它用于收集多个 Redis 命令，最后通过 Exec() 一次性提交执行。

帖子设计

MySQL 只存帖子详细信息、社区详细信息、用户信息、评论信息。
Redis 负责存储和管理投票数据
为什么这样设计？

  1. Redis 适合高频读写的场景
    由于帖子投票可能会频繁更新（点赞、踩、撤销投票等），如果直接存 MySQL，频繁 UPDATE 会导致性能瓶颈。
    而 Redis 支持高并发读写，可以使用 ZSet 结构存储帖子 ID 及其得分，方便排序查询。
  2. 快速排序
    投票数影响帖子排序（比如“最热帖子”按投票数排名），存 Redis 可以用 ZSet 进行 快速排序
