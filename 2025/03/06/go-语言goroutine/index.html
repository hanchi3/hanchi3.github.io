📖 协程 - GMP、内存管理、编译运行

|Word Count:3.3k|Reading Time:10mins|Post Views:

总览：go 编译和运行的完整过程

1️⃣ 编写 Go 源代码

使用 .go 扩展名的文件编写代码。

2️⃣ 编译过程

将源代码（.go 文件）转换为可执行文件，Go 编译过程大致可以分为以下几个步骤：

  1. 源代码解析：编译器首先读取 .go 源代码文件。语法解析器（Parser）对源代码进行词法分析，检查源代码是否符合 Go 语言的语法规则。

  2. 语法树生成：编译器将源代码转换为语法树（AST，Abstract Syntax Tree），即代码的结构化表示。AST 是语法分析的结果，表示程序的各个组成部分，如函数、变量、结构体等。

  3. 类型检查：在这一步，编译器会检查变量和函数等元素的类型是否匹配，确保符合 Go 语言的类型系统。Go 是强类型语言，编译器会检测类型错误，比如将整数赋给字符串类型的变量。

  4. 中间代码生成：编译器会将语法树转换为中间表示（IR），这是一种简化的、与硬件无关的代码形式，比源代码更加简洁。。中间代码用于后续的优化和生成机器代码。

  5. 优化：编译器在中间表示上进行一些优化，如死代码消除（removal of unreachable code）和常量折叠（constant folding）等。这些优化有助于提高程序的执行效率。

  6. 生成目标代码：编译器将中间代码转化为特定平台的机器码，通常为目标操作系统（如 Windows、Linux）和架构（如 x86 或 ARM）特定的二进制可执行文件。编译器会生成一个静态或动态链接的目标文件。

  7. 链接：编译过程是针对单个文件进行的，文件与文件之间不可避免地要引用定义在其他模块的全局变量或者函数，这些变量或函数的地址只有在此阶段才能确定。链接过程就是要把编译器生成的一个个目标文件链接成可执行文件。链接器将目标文件中的代码与 Go 运行时（Runtime）、标准库及外部库链接，生成最终的可执行文件。由于 Go 是编译成静态链接的二进制文件（除非手动指定使用共享库），所有依赖的库都被嵌入到最终的可执行文件中。

3️⃣ 执行过程

前言：Go 程序的执行由两层组成：Go Program，Runtime。它们之间通过函数调用来实现内存管理、channel 通信、goroutines 创建等功能。用户程序进行的系统调用都会被 Runtime 拦截，以此来帮助它进行调度以及垃圾回收相关的工作。

  1. 加载执行文件：操作系统加载程序的二进制代码到内存中，并启动程序的入口点（main 函数）。

  2. Go 运行时初始化：Go 程序的运行时（runtime）开始初始化，设置内存管理、垃圾回收器、调度器等。程序的 main 函数开始执行，并初始化相关的变量和资源。

  3. 调度（Scheduler）：Go Runtime 开始管理 goroutines。Go 使用 M:N 调度模型，将多个 goroutines 映射到操作系统线程上。运行时通过抢占式调度和协作式调度确保程序并发执行。

  4. Goroutine 执行：每个 goroutine 都有自己的栈，Runtime 负责管理所有 goroutines 的创建、调度和执行。当 goroutine 执行过程中发生阻塞（如等待 I/O、同步等），调度器会切换到其他可运行的 goroutine。

  5. 内存管理和垃圾回收：Runtime 管理内存分配和释放。通过垃圾回收机制（GC）自动清理不再使用的内存，减少内存泄漏的风险。

  6. 处理 I/O 和信号：Go Runtime 通过 I/O 多路复用（如 epoll、kqueue 等）和信号处理来支持高效的网络和 I/O 操作。

  7. 程序退出：当 main 函数执行完毕，Go 程序的执行完成，程序退出。Runtime进行清理工作，如关闭文件、释放资源等。

goroutine 和线程的区别

定义

  • 进程：是应用程序的启动实例，每个进程都有独立的内存空间，不同的进程通过进程间的通信方式来通信。
  • 线程：从属于进程，每个进程至少包含一个线程，线程是 CPU 调度的基本单位，多个线程之间可以共享进程的资源并通过共享内存等线程间的通信方式来通信。
  • 协程：为轻量级线程，与线程相比，协程不受操作系统的调度，协程的调度器由用户应用程序提供，协程调度器按照调度策略把协程调度到线程中运行。

内存占用区别

创建一个 goroutine 的栈内存消耗为 2 KB，实际运行过程中，如果栈空间不够用，会自动进行扩容。创建一个 thread 则需要消耗 1 MB 栈内存，而且还需要一个被称为 “a guard page” 的区域用于和其他 thread 的栈空间进行隔离。

对于一个用 Go 构建的 HTTP Server 而言，对到来的每个请求，创建一个 goroutine 用来处理是非常轻松的一件事。而如果用一个使用线程作为并发原语的语言构建的服务，例如 Java 来说，每个请求对应一个线程则太浪费资源了，很快就会出 OOM 错误（OutOfMemoryError）。

创建和销毀区别

Thread 创建和销毀都会有巨大的消耗，因为要和操作系统打交道，是内核级的，通常解决的办法就是线程池。而 goroutine 因为是由 Go runtime 负责管理的，创建和销毁的消耗非常小，是用户级。

切换区别

当 threads 切换时，需要保存各种寄存器，以便将来恢复；而 goroutines 切换只需保存三个寄存器：Program Counter, Stack Pointer and BP。
一般而言，线程切换会消耗 1000-1500 纳秒，Goroutine 的切换约为 200 ns，因此，goroutines 切换成本比 threads 要小得多。

GMP 模型

三个基础的结构体来实现 goroutines 的调度。g，m，p。
G 代表着 goroutine，P 代表着上下文处理器 Processor，M 代表操作系统内核 thread 线程。在 GPM 模型，有一个全局队列（Global Queue）：存放等待运行的 G，还有一个 P 的本地队列：也是存放等待运行的 G，但数量有限，不超过 256 个。

G,P,M 的个数问题

  1. G（Goroutine）的个数：理论上无限制，因为goroutine比线程更轻量级。但实际上它们会受到系统可用内存的限制。

  2. P（Processor）的个数：通常设置为逻辑CPU数的两倍，为了提高调度的并行性和效率。每个P都可以绑定到一个M上执行goroutine，而设置更多的P可以使得在某些M阻塞时，其他M仍然可以执行P上的goroutine，从而减少等待时间。P的实际数量由环境变量 GOMAXPROCS 决定。这个值限制了同时运行的goroutine的数量，即在任何给定时间，最多只有 GOMAXPROCS 个goroutine在CPU上执行。

  3. M（Machine/Thread）的个数：动态创建和销毁：M的数量是动态变化的，Go运行时根据需要创建和销毁M。当一个M上的所有goroutine都阻塞时，该M可能会被销毁，而当有goroutine等待执行但没有可用的M时，会创建新的M。Go程序启动时，会设置一个M的最大数量（默认通常是10000，但这个限制很少达到，因为操作系统本身就有线程/进程数量的限制。

M与P之间没有绝对的固定关系。**一个M可以绑定到任意P上执行goroutine，而当M阻塞时，它会释放其绑定的P，P随后会尝试绑定到其他空闲的M上。**因此，即使P的数量较少，也可能因为工作量窃取和M的动态创建而有大量的M存在（尽管这些M中的大多数可能在等待中）。

Go scheduler

Go Scheduler（调度器）是什么？

Go scheduler 可以说是 Go Runtime 的一个最重要的部分了。Runtime 维护所有的 goroutines，scheduler 负责调度 goroutines 的执行。它的作用是 管理 goroutine 的执行，合理分配 CPU 资源，保证高效并发运行，同时避免过多的线程切换带来的性能损耗。
由于 Go 语言使用了 goroutine 这种轻量级线程，而 goroutine 的数量通常远远超过操作系统线程的数量，因此需要一个高效的调度器来 在少量的 OS 线程上调度大量的 goroutines，避免 goroutine 直接与 OS 线程绑定带来的开销。

📌 调度流程

  1. 创建 Goroutine：
    当通过 go func() 创建新的 Goroutine 时，G 会首先被加入到与当前 P 关联的本地队列中。
    如果 P 的本地队列已满（超过 256 个 G），则新的 G 会被放入全局队列。
  2. 调度与执行：
  • 每个 M 与一个 P 绑定，M 从 P 的本地队列中获取一个 G 来执行。
  • 如果 P 的本地队列为空，M 会尝试从全局队列或其他 P 的本地队列中偷取（work stealing 机制）任务执行，保证 CPU 资源利用率。
  1. 系统调用与阻塞：
  • 当 G 执行过程中发生阻塞或系统调用，M 也会被阻塞。这时，P 会解绑当前的 M，并尝试寻找或创建新的 M 来继续执行其他 G。hand off（移交）机制
  • 阻塞结束后，原来的 M 会尝试重新绑定一个 P 继续执行。

scheduler 设计策略

0️⃣ 前提：采用 GMP 模型：
✅ 减少锁竞争：P 绑定 M，减少 G 在不同线程间频繁切换
✅ 避免 OS 线程创建销毁的开销：复用 M，提高执行效率
✅ 最大化 CPU 核心利用率：动态调度 P，使 CPU 资源尽可能忙碌

1️⃣ 局部性原则（Locality）：。Go 采用 P 维护本地运行队列，让 Goroutine 尽量在同一个线程上执行，减少线程切换开销。
✅ 局部队列调度：P 维护自己的 G 队列，M 只从本地队列取任务，避免全局竞争
✅ 减少全局锁开销：只有当 P 的队列为空时，才从全局队列或其他 P 窃取任务

2️⃣ Work Stealing（工作窃取）：当某个 P 处理完自己的 G 任务后，它会尝试从 其他 P 的本地队列里“偷”任务，避免 CPU 资源闲置。
✅ 提高 CPU 资源利用率：如果某个 P 任务少，而其他 P 任务多，可以动态平衡任务负载
✅ 减少全局队列访问：减少锁争用，提升吞吐量

3️⃣ 抢占式调度：在 Go 1.14 之前，G 只有在**主动让出 CPU（如调用函数、GC、I/O 阻塞）**时才会被调度，导致计算密集型任务可能长期占用 CPU，影响其他 G 的执行。
Go 1.14 之后，引入抢占式调度：运行时定期触发调度检查，如果 G 占用 CPU 过长，运行时会强制暂停它并切换任务。
✅ 防止 Goroutine 长时间独占 CPU，提高公平性
✅ 提升 Go 在高并发场景下的响应能力

4️⃣ GOMAXPROCS 动态调整：Go 运行时允许动态调整 GOMAXPROCS（P 的数量），适配不同的 CPU 负载情况。在高负载情况下，Go 会自动扩展 P，提高并发能力。
✅ 根据 CPU 负载动态调整，充分利用多核 CPU
✅ 减少 P 过多导致的线程竞争，提升调度效率

5️⃣ 结合 GC（垃圾回收）优化调度：Go 运行时采用 并发 GC，调度器会与 GC 协同工作，确保 GC 运行时不会影响 Goroutine 执行。调度器会优先调度 GC 相关 Goroutine，确保垃圾回收尽快完成。
✅ GC 和 Goroutine 运行并行，减少 GC 影响
✅ STW 时间最小化，保证应用流畅运行

6️⃣ I/O 多路复用（netpoller）：在处理 网络 I/O 时，Go 调度器集成了 epoll（Linux）、kqueue（macOS）、IOCP（Windows），避免 Goroutine 被阻塞。Goroutine 进行网络 I/O 时，不会阻塞 M，而是放入 netpoller 监听事件。当 I/O 事件触发后，调度器会重新唤醒 G 并执行
✅ 高效处理网络请求，大幅减少 Goroutine 阻塞
✅ 适用于高并发 Web 服务器（如 Gin、gRPC）

什么是 M:N 模型

Runtime 会在程序启动的时候，创建 M 个线程（CPU 执行调度的单位），之后创建的 N 个 goroutine 都会依附在这 M 个线程上执行。这就是 M:N 模型。
在同一时刻，一个线程上只能跑一个 goroutine。当 goroutine 发生阻塞时，runtime 会把当前 goroutine 调度走，让其他 goroutine 来执行。目的就是不让一个线程闲着，榨干 CPU 的每一滴油水。
