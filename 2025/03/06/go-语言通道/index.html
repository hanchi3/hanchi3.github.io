📖 通道channel - 并发编程的核心工具

Created2025-03-06|Updated2025-03-06|go基础
|Word Count:2.1k|Reading Time:7mins|Post Views:

什么是 CSP

不要通过共享内存来通信，而要通过通信来实现内存共享。

  • 在很多主流的编程语言中，多线程使用共享内存传递数据，多个线程传递数据的方式一般都是共享内存，为了解决线程竞争，我们需要限制同一时间能够读写这些变量的线程数量，然而这与 Go 语言鼓励的设计并不相同。

  • Go中，也能使用共享内存加互斥锁进行通信，但是 Go 语言提供了一种不同的并发模型，通信顺序进程（Communicating sequential processes，CSP）。Goroutine 使用 Channel 传递数据，Goroutine 和线程类似，channel 和 mutex (用于内存同步访问控制)类似。两个 Goroutine，一个会向 Channel 中发送数据，另一个会从 Channel 中接收数据，它们两者能够独立运行并不存在直接关联，但是能通过 Channel 间接完成通信。

Goroutine 解放了程序员，让我们更能贴近业务去思考问题。而不用考虑各种像线程库、线程开销、线程调度等等这些繁琐的底层问题，goroutine 天生替你解决好了。

Channel 则天生就可以和其他 channel 组合。我们可以把收集各种子系统结果的 channel 输入到同一个 channel。Channel 还可以和 select, cancel, timeout 结合起来。而 mutex 就没有这些功能。

Go 的并发原则非常优秀，目标就是简单：尽量使用 channel；把 goroutine 当作免费的资源，随便用。

channel 基本概念

特性

类型安全：channel 是带类型的，只能传递特定类型的数据。
同步通信：channel 通过 goroutine 间的阻塞机制 来同步数据传输，避免竞争条件。
多种通信模式：可以是有缓冲或无缓冲的。

数据结构


总结hchan结构体的主要组成部分有四个：

  • 用来保存 goroutine 之间传递数据的循环数组。=====> buf。只有缓冲型的 channel 才有。
  • 用来记录此循环链表当前发送或接收数据的下标值。=====> sendx和recvx。
  • 用于保存向该 chan 发送和从改 chan 接收数据的被阻塞的 goroutine 的队列。=====> sendq 和 recvq
  • 保证channel写入和读取数据时线程安全的锁。 =====> lock

创建 channel

使用 make() 创建：

从函数原型来看，创建的 chan 是一个指针。所以我们能在函数间直接传递 channel，而不用传递 channel 的指针。

channel 的操作

向 channel 发送数据

向一个channel中写数据简单过程如下：

  • 检查是否有等待接收的 Goroutine（recvq 不为空）。如果 channel 为空（无缓冲或缓冲区已满），但是有 Goroutine 在等待接收，那么发送方会直接将数据传递给接收方，用不着通过 channel 的 buf “中转”一次，并唤醒该 Goroutine 继续运行。
  • 检查缓冲区是否有空间。如果 channel 是有缓冲的，并且缓冲区未满，则数据会写入缓冲区队尾，发送 Goroutine 继续运行，不会阻塞。
  • 缓冲区满时，发送 Goroutine 进入等待队列（sendq）。进入睡眠，等待被读goroutine唤醒。

从 channel 接收数据

从一个channel读数据简单过程如下：

  • 如果等待发送队列 sendq 不为空，且没有缓冲区，直接从 sendq 中取出G，把G中数据读出，最后把G唤醒，结束读取过程。
  • 如果等待发送队列 sendq 不为空，有缓冲区，此时说明缓冲区已满，从缓冲区中首部读出数据，把G中数据写入缓冲区尾部，把G唤醒，结束读取过程。
  • sendq 空，如果缓冲区中有数据，则从缓冲区取出数据，结束读取过程；
  • sendq 空，缓冲区没有数据，将当前 goroutine 加入 recvq，进入睡眠，等待被写 goroutine 唤醒。

关闭 channel

关闭 channel 后，对于等待接收者而言，会把 recvq 中的G全部唤醒，本该写入G的数据位置为nil。对于等待发送者，把 sendq 中的G全部唤醒，会直接 panic。

channel 在什么情况下会引起资源泄漏

泄漏的原因是 goroutine 操作 channel 后，处于发送或接收阻塞状态，而 channel 处于满或空的状态，一直得不到改变。同时，垃圾回收器也不会回收此类资源，进而导致 gouroutine 会一直处于等待队列中，不见天日。

另外，程序运行过程中，对于一个 channel，如果没有任何 goroutine 引用了，gc 会对其进行回收操作，不会引起内存泄漏。

本质

channel 的发送和接收操作本质上都是 “值的拷贝”，在底层就是一个用来存储数据的缓冲区。 通过同步机制来保证 Goroutine 之间的数据安全和顺序执行。

channel 有哪些应用

select：
select 语句是 Go 中处理并发操作的一种强大工具。
select 语句用于在多个通道（channels）之间进行选择。当多个通道都有可操作的数据时，select 会选择其中一个通道进行操作。如果有多个通道都准备好了，select 会随机选择一个。

传递数据

通过 channel，我们可以实现两个 goroutine 之间的数据传递。例如，一个 goroutine 生成数据并发送到 channel，另一个 goroutine 从 channel 中接收数据并进行处理。例如并发的任务结果收集、任务调度等。

任务定时

超时控制，有时候，需要执行某项操作，但又不想它耗费太长时间，上一个定时器就可以搞定：若在 100 毫秒内 s.stopc 通道被关闭或接收到数据，那么就会提前退出（return false）。如果 stopc 通道没有数据，它会等待 100 毫秒，并且在超时后继续执行后续的代码。

定期执行任务，每隔 1 秒执行一次定时任务。定时器使用了 time.Tick 来周期性地触发事件。在每次 select 阻塞等待的过程中，每隔 1 秒钟就会收到一个来自 ticker 通道的信号，并执行相应的任务。这种方式常用于执行周期性的任务。

解耦生产方和消费方

  • 生产方（主程序）不关心任务被哪个工作协程处理，它只管把任务投递到 channel 中。
  • 消费者（工作协程池）从 channel 中消费任务并执行，不知道生产方的存在，并且通过启动多个工作协程（5 个），它们共同消费任务。这样，工作负载被分摊到多个协程上，提高了并发性和处理效率。
  • 产者和消费者可以独立运行，彼此解耦。

控制并发数

通过 channel 的缓冲容量来控制并发数，能有效避免一次性启动过多 goroutine，从而保护系统的资源。
