web-gee-5🚀 中间件 Middleware

Created2025-03-06|Updated2025-03-07|轮子
|Word Count:1.2k|Reading Time:4mins|Post Views:

web-gee-5 中框架实现的功能

  1. 给 Context 添加 handlers 和 index 字段，定义了 c.Next() 方法。handlers[index] 就可以定位到具体的处理方法。

  2. 给RouterGroup 添加middlewares []HandlerFunc字段， Use() 添加方法到 middlewares 注册路由。

  3. 解析路由，ServeHTTP()，全局和分组中间件在此加入 handlers。

  4. handle() ，路由匹配的 HandlerFunc 在此加入 handlers，且执行 c.Next() 为方法调用入口。

中间件是什么

中间件(middlewares)，简单说，就是非业务的技术类组件。Web 框架本身不可能去理解所有的业务，因而不可能实现所有的功能。因此，框架需要有一个插口，允许用户自己定义功能，嵌入到框架中，仿佛这个功能是框架原生支持的一样。

中间件想要实现的效果

Gee 的中间件的定义与路由映射的 Handler 一致，处理的输入是Context对象。插入点是框架接收到请求初始化Context对象后，允许用户使用自己定义的中间件做一些额外的处理，例如记录日志等，以及对Context进行二次加工。
另外通过调用 (*Context).Next() 函数，中间件可等待用户自己定义的 Handler处理结束后，再做一些额外的操作，例如计算本次处理所用时间等。另外，支持设置多个中间件，依次进行调用。

实现

  • 中间件是应用在RouterGroup上的，应用在最顶层的 Group，相当于作用于全局。

  • 接收到请求后，应查找所有应作用于该路由的中间件，保存在Context中，依次进行调用。（因为在设计中，中间件也可以作用在用户定义的 Handler 处理完毕后，还可以执行剩下的操作。

Context 和 c.Next()方法实现

给 Context 添加了2个参数，定义了 Next 方法:

  • handlers 是一个切片，存储所有应该执行的函数，列表包含全局中间件、Group 中间件、匹配路由的 Handler。

  • index 是记录当前执行到第几个中间件，当在中间件中调用 Next 方法时，控制权交给了下一个中间件，直到调用到最后一个中间件，然后再从后往前，调用每个中间件在 Next 方法之后定义的部分。

  • c.Next() 递增 index，调用下一个 handlers[index]，支持 调用后继续执行，因此形成 前进 - 回溯 结构。

Use() 注册路由

  • 注册中间件到 engine.groups[0].middlewares 切片。
  • middlewares []HandlerFunc 是 RouterGroup 的一个字段

ServeHTTP() 解析 全局和分组中间件在此加入 handlers

  • 遍历 engine.groups
  • 解析 URL 路由，找到适用的 RouterGroup
  • 获取该 Group 的所有中间件，存入 middlewares
  • 将 middlewares 赋值给 c.handlers
  • 调用 handle()，执行业务逻辑

handle() 解析 路由匹配的 HandlerFunc在此加入handlers

📌 这里的 c.handlers 形成完整的调用链

  • 先执行 RouterGroup 绑定的中间件
  • 调用 c.Next() 执行（handlers里的顺序是middlewares在前）。

执行过程

假设 handlers = [Logger, Auth, RouteHandler]，调用顺序如下：

  1. Logger(c) 执行，遇到 c.Next()
    c.index++，进入 Auth
  2. Auth(c) 执行，遇到 c.Next()
    c.index++，进入 RouteHandler
  3. RouteHandler(c) 执行，c.Next() 结束，开始回溯
    回到 Auth 中 Next() 之后部分
    回到 Logger 中 Next() 之后部分
