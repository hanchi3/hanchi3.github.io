gRPC、微服务

RPC（Remote Procedure Call）

什么是RPC？

RPC，即远程过程调用，是一种让程序像调用本地函数一样调用远程服务的技术。它的核心思想是屏蔽网络通信的复杂性，让开发者专注于业务逻辑，而不是底层的网络传输细节。

RPC的底层原理

  1. 客户端调用代理（Stub）
    在客户端，开发者调用一个本地函数（称为Stub或代理），这个函数看起来像普通的本地函数，但实际上它负责与远程服务器通信。Stub的作用是将函数调用转化为网络请求。

  2. 序列化（Serialization）
    Stub会把函数的参数（例如整数、字符串、结构体等）序列化成字节流。常见的序列化格式包括JSON、XML或自定义的二进制格式。序列化的目的是将数据转换为可以在网络上传输的格式。

  3. 网络传输
    序列化后的数据通过网络协议（如TCP/IP）发送到远程服务器。客户端Stub通常会与服务器建立连接（可能是短连接或长连接），然后将请求数据发送出去。

  4. 服务器端Stub接收
    在服务器端，有一个对应的Stub（也叫Skeleton），负责接收客户端发送的字节流。服务器Stub将字节流反序列化，恢复成原始的参数。

  5. 执行实际函数
    服务器端Stub调用真正的业务逻辑函数，传入反序列化后的参数，执行计算或操作。

  6. 返回结果
    函数执行完成后，返回值（如果有）会被服务器Stub再次序列化成字节流，通过网络传回客户端。客户端Stub接收后反序列化，将结果返回给调用者，完成整个过程。

RPC的关键组件

  • IDL（接口定义语言）：通常用一种中间语言（如Thrift的IDL或Protocol Buffers）定义服务接口，描述函数名、参数和返回值类型。
  • 通信协议：底层的网络传输协议（如TCP或UDP）。
  • 序列化/反序列化：决定了数据在网络中的编码效率和兼容性。

gRPC

什么是gRPC？

gRPC 是 Google 开发的一种高性能、开源的RPC框架，基于HTTP/2协议和Protocol Buffers（简称ProtoBuf）。它在传统RPC的基础上进行了现代化改进，支持双向流、多语言和高效通信。

gRPC的底层原理

基于HTTP/2

  • gRPC 使用 HTTP/2 作为传输协议，相比HTTP/1.1有以下优势：
    多路复用：允许在同一个TCP连接上并行发送多个请求和响应，避免了传统RPC中“队头阻塞”问题。
    头部压缩：通过HPACK压缩HTTP头部，减少传输开销。
    双向流：支持客户端和服务器同时发送数据流，适用于实时通信场景。
  • gRPC 不直接依赖HTTP的语义（如GET/POST），而是将RPC调用封装在HTTP/2的POST请求中，路径和方法名通过元数据传递。

Protocol Buffers（ProtoBuf）

gRPC 默认使用 ProtoBuf 作为序列化格式。ProtoBuf 是一种二进制序列化协议，具有以下特点：

  • 高效：相比JSON或XML，生成的字节流更小，序列化/反序列化速度更快。
  • 强类型：通过.proto文件定义服务和消息结构，编译生成多语言的代码（如Java、Go、Python等）。
  • 向后兼容：支持字段扩展而不破坏已有代码。

服务定义与Stub生成

  • 开发者用ProtoBuf定义服务接口后，gRPC工具（如protoc编译器）会生成客户端和服务器端的Stub代码。
  • 客户端Stub负责发起调用，服务器Stub负责实现服务逻辑。

通信流程

  • 客户端：
    调用Stub方法（如SayHello）。
    Stub将请求序列化为ProtoBuf字节流。
    通过HTTP/2发送到服务器。
  • 服务器：
    接收HTTP/2请求，反序列化ProtoBuf数据。
    调用实现的服务逻辑。
    将结果序列化后通过HTTP/2返回。
  • 客户端：接收响应，反序列化后返回给调用者。

支持四种调用模式

  • 一元调用（Unary）：类似传统RPC，单次请求-响应。
  • 服务器流（Server Streaming）：客户端发送一个请求，服务器返回数据流。
  • 客户端流（Client Streaming）：客户端发送数据流，服务器返回一个响应。
  • 双向流（Bidirectional Streaming）：客户端和服务器同时发送和接收数据流。

gRPC的关键特性

  • 高性能：HTTP/2的多路复用和ProtoBuf的二进制编码显著提升了效率。
  • 多语言支持：通过ProtoBuf生成代码，支持C++、Java、Go、Python等。
  • 流式通信：支持实时、双向数据传输，适用于现代分布式系统。
  • 拦截器（Interceptor）：允许在请求/响应中插入中间件（如认证、日志）。

go-zero

go-zero 是什么？

go-zero 是由 zeromicro 团队开发的一个开源微服务框架，最初发布于 2020 年。它是一个集成了多种工程实践的 Web 和 RPC 框架，基于 Go 语言设计，特别强调弹性设计（resilience design）以保证大并发服务的稳定性。

其核心目标是：

  • 提升开发效率：通过代码生成工具 goctl，减少重复性工作。
  • 保障服务稳定性：内置微服务治理功能，如限流、熔断、负载均衡等。
  • 支持现代化架构：基于 gRPC 和 HTTP，提供云原生支持。

go-zero 的官方口号是“缩短从需求到上线的距离”，它通过自动化工具和预置功能，让开发者专注于业务逻辑而非底层实现。

go-zero 的架构设计

go-zero 的架构可以分为以下几个层次：

  1. 通信层（gRPC + HTTP）

    • go-zero 的 RPC 模块（zRPC）基于 gRPC，封装了 gRPC 的服务端和客户端逻辑，默认使用 HTTP/2 和 Protocol Buffers（ProtoBuf）进行高效通信。
    • 在 TCP 监听器（net.Listen）之上，go-zero 使用 gRPC 的 HTTP/2 协议栈处理请求，开发者无需关心底层细节。
    • RESTful API 通过 gRPC Gateway 实现，自动将 gRPC 调用映射为 HTTP 请求。

  2. 服务治理层

    • 服务发现：内置支持 etcd、Consul 等服务注册中心，也支持 Kubernetes 原生服务发现。
    • 负载均衡：默认实现 P2C（Power of Two Choices）算法，优化请求分发。
    • 稳定性保障：提供限流（rate limiting）、熔断（circuit breaker）、自适应降载（load shedding）等功能，无需额外配置。

  3. 应用层

    • 通过 goctl 生成的代码框架，包括服务端逻辑、配置文件、依赖注入等。
    • 支持中间件机制，允许开发者插入自定义逻辑（如认证、日志、监控）。

  4. 工具层（goctl）

    • goctl 是 go-zero 的核心工具，支持从 .proto 或 .api 文件生成多语言代码（Go、JavaScript、Dart 等），并生成完整的服务框架。
    • goctl 调用 protoc 和插件（如 protoc-gen-go 和 protoc-gen-go-grpc）生成 gRPC 代码。
    • 基于模板引擎，生成 go-zero 的服务框架代码，结构清晰且符合 Go 惯例。

整体架构遵循“微服务开箱即用”的理念，开发者只需“填空”式地实现业务逻辑即可。

自动生成代码

组成部分：

  1. goctl rpc protoc

    • goctl 是 go-zero 提供的命令行工具。
    • rpc 子命令表示这是针对 RPC 服务的代码生成。
    • protoc 是 Protocol Buffers 的编译器，goctl 在这里调用了 protoc 来解析 .proto 文件。

  2. ./user.proto

    • 这是输入文件，即你的 Protocol Buffers 定义文件，里面包含了服务和消息的定义。

  3. gRPC 和 ProtoBuf 相关代码（由 protoc 生成）

    --go_out=.

    • 这是 protoc 的参数，告诉 protoc 生成 Go 语言的基础代码（主要是消息结构的定义）。
    • 它依赖 protoc-gen-go 插件，生成的是包含 ProtoBuf 消息结构体的 Go 代码（不包含 gRPC 相关逻辑）。定义了消息的序列化/反序列化逻辑和结构体。例如：rpc/service/user.pb.go。

    --go-grpc_out=.

    • 这是 protoc 的另一个参数，告诉 protoc 生成 gRPC 的 Go 语言代码。
    • 它依赖 protoc-gen-go-grpc 插件，生成的是 gRPC 的服务端和客户端 Stub 代码。定义了服务的接口和通信逻辑。例如：rpc/service/user_grpc.pb.go。

    直接依赖于 user.proto 文件的定义。它们是 gRPC 的标准输出，与 go-zero 无关，即使不使用 go-zero，也可以单独使用这些文件实现 gRPC 服务。

  4. go-zero 的 zRPC 框架代码

    --zrpc_out=./

    • 这是 goctl 特有的参数，表示生成 go-zero 的 zRPC 框架代码。
    • 它会在指定目录（./）下生成基于 go-zero 的服务框架代码，包括配置文件、服务逻辑模板等。

    包含：

    • rpc/etc/user.yaml 作用：服务的配置文件，定义端口、服务名、etcd 等参数。
    • rpc/internal/config/config.go 作用：定义配置结构体，与 user.yaml 对应，用于加载配置。
    • rpc/internal/logic/ 作用：业务逻辑的实现模板，每个文件对应 user.proto 中定义的一个 RPC 方法。
    • rpc/internal/model/ 作用：数据访问层代码，用于与数据库交互。由 goctl model 命令额外生成。
    • rpc/internal/server/userserver.go 作用：gRPC 服务端实现，调用 logic 层的代码。
    • rpc/internal/svc/servicecontext.go 作用：服务上下文，管理依赖（如数据库、缓存）。
    • rpc/user.go 作用：服务的主入口，启动 zRPC 服务。

    这些文件是 go-zero 的 zRPC 框架的一部分，依赖于 gRPC 生成的 user.pb.go 和 user_grpc.pb.go。它们提供了配置、逻辑层、服务上下文等功能，形成一个完整的微服务框架。
