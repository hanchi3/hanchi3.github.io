📌论坛项目架构 - gRPC 接入 etcd 实现服务注册与发现

Created2025-04-02|Updated2025-04-04
|Word Count:1.8k|Reading Time:7mins|Post Views:

基本概念

gRPC 客户端的服务发现

通常情况下客户端需要知道服务端的 IP + 端口号 才能建立连接，但服务端的 IP 和端口号并不是那么容易记忆。还有更重要的，在云部署的环境中，服务端的 IP 和端口可能随时会发生变化。

所以我们可以给某一个服务起一个名字，客户端通过名字创建与服务端的连接，客户端底层使用服务发现系统，解析这个名字来获取真正的 IP 和端口，并在服务端的 IP 和端口发生变化时，重新建立连接。这样的系统通常也会被叫做 name-system（名字服务）。（名字服务的概念很重要，下面会有用到）

注册中心应用场景：

  1. 如果服务端 ip:port 变动，只需要修改存储在注册中心的 key:value 的对应值；
  2. 一般注册中心都有类似于心跳的功能，能够检查 rpc 服务端是否正常运行；
  3. 一个 rpc 服务有多个服务器实例，客户端可以通过相同的名字拉取到所有的地址；

gPRC 服务端的服务注册

在微服务架构中，一个服务（比如订单服务）可能会部署多个实例，客户端（比如网关）要知道这些实例的地址，才能访问它们。如果 gRPC 服务端的地址是静态的，可以在客户端服务发现时直接解析为静态的地址。

如果 gRPC 服务端的地址是动态的，可以有两种选择：

  1. 自注册：当 gRPC 的服务启动后，向一个集中的注册中心进行注册，改变时客户端可以感知到（就是今天学习的 etcd）；
  2. 平台的服务注册：Kubernetes 有内建的服务注册机制，本质上是它自动把服务注册到了自己的 etcd 中。平台会感知 gPRC 实例的变化，比如重启、扩缩容。

RPC 的负载均衡

负载均衡发生的前提条件是有多台完全相同的 RPC 服务端。不然压根就不需要 = 负载均衡。

为什么是etcd

具体的整体逻辑

etcd（服务注册中心）

etcd 作为一个分布式键值存储，扮演服务注册与发现的中心角色。它的工作包括：

  • 存储服务信息:

    • 提供键值存储，用于保存微服务的注册信息。
    • 键通常是服务名称（如 /services/user），值是服务地址（如 localhost:8081）。

  • 租约管理（Lease）:

    • 支持租约机制，确保服务注册的键具有生存时间（TTL）。
    • 如果服务未续约，租约到期后自动删除对应键，保持数据一致性。

  • 事件通知:

    • 通过 Watch API 提供键值变化的实时通知（Put、Delete 等事件）。
    • 客户端可以订阅特定键的变化，获取服务上线或下线的通知。

  • 高可用性:

    • 在集群模式下，etcd 确保数据一致性和高可用性（需配置多个节点）。

服务端（微服务实例，如 user-service）

服务端负责将自身注册到 etcd，并保持注册信息有效。典型工作如下：

  • 服务注册:

    • 在启动时，将服务信息（名称和地址）写入 etcd。
    • 使用键值对表示，例如：
      • 键: /services/user
      • 值: localhost:8081
    • 绑定租约（Lease），设置 TTL（如 10 秒）。

  • 续约（KeepAlive）:

    • 定期向 etcd 发送续约请求，保持租约有效。
    • 如果服务停止，停止续约，租约到期后键自动删除。

客户端（消费者，如 bff）

客户端（如 bff）负责从 etcd 发现服务地址并与之通信。典型工作如下：

  • 服务发现:

  • 查询 etcd 获取服务地址（如 /services/user 的值 localhost:8081）。

  • 支持动态解析，确保连接到最新的服务实例。

  • 监听变化:

    • 使用 Watch 监听服务地址的变化（上线或下线）。
    • 更新本地连接状态（如 gRPC 连接）。

  • 建立连接:

    • 使用发现的地址与服务端建立通信（通常是 gRPC 或 HTTP）。

各端协作流程

  1. 服务端（user-service）:
  • 启动时注册 /services/user -> localhost:8081，绑定租约。
  • 持续续约，保持键存在。
  1. etcd:
  • 存储键值，管理租约。
  • 通知客户端键变化。
  1. 客户端（bff）:
  • 查询 /services/user，获取 localhost:8081。
  • 监听变化，动态更新 gRPC 连接。
  • 调用 user-service 的 gRPC 方法。
